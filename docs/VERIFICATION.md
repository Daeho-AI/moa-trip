# v0.5.0 검증 기록

2026-11-15. 경유지 함께 들르기를 추가한 뒤 Linux의 실제 Pleos 에뮬레이터 두 대에서 검증했다.

| 검사 | 결과 |
|---|---|
| Kotlin 핵심 규칙 / 서버 | 20 / 23개 통과 |
| 목적지 회귀 검사 | 42개 확인 항목 통과 |
| 순정 내비 위 승인·거절, Drive 30 km/h, 위치·ETA | 20개 확인 항목 통과 |
| 경유지 추가·개인 경유지 순서·2곳 제한·거절·재시작·삭제 후 재추가 방지 | 중복 준비 검사를 제외한 24개 확인 항목 통과 |
| 배포 앱 | v0.5.0 / versionCode 6, release, debuggable=false, 기존 제출 키의 v3 서명 |

경유지 검사는 참여 차량에 양수역 개인 경유지를 먼저 등록한 뒤 세미원을 추가했다. 목적지는 두물머리주차장으로 유지되고, 개인 경유지 다음에 공동 경유지가 들어갔다. 이후 세 번째 장소 제안에서는 기존 두 경유지를 보존하고 추가를 차단했다. 승인·거절 후 앱을 다시 시작해도 중복 요청이 없었고, 순정 내비에서 경유지를 제거해도 복원하지 않았다.

현재 이미지의 경유지 조회 좌표는 `0,0`이다. 좌표 일치를 성공으로 표시하지 않고, 확인한 에뮬레이터 조합에만 POI ID 기반 추가를 허용한다. 목적지는 좌표를 포함해 비교하고 경유지는 ID·이름·주소·순서를 두 번 재조회한다. 상세한 제한과 추가 검증 범위는 [경유지 설명](WAYPOINTS.md), 실제 확인 항목은 [v050.json](verification/v050.json)에 있다.

아래는 이전 배포의 이력이다. 공동 경유지 **단일 추가**에 관한 미완료 표기는 위 v0.5.0 범위로 대체한다. 지도 마커·휴게소 추천·픽업 최적화·일반 휴대폰 참여·실차 검증은 포함하지 않는다.

## 이전 v0.4.3 검증 기록

2026-11-15에 같은 두 Pleos 에뮬레이터에서 다시 확인했다. 기존 앱 흐름은 **40/40**, 새 순정 내비 위 알림 흐름은 **18/18** 통과했다. [기존 흐름 결과](verification/2026-11-15-regression.json), [배경 흐름 결과](verification/2026-11-15-background.json). 기존 흐름 40개에는 이전 시험방 종료·복원 점검도 포함된다.

| 새 확인 항목 | 결과 |
|---|---|
| 리더의 순정 내비 위 알림 | 나만 변경은 계획을 게시하지 않고, 일행에게 요청은 해당 목적지를 공유 |
| 참여 차량의 거절 | 모아트립 화면을 열지 않고 기존 DOT42 목적지 유지, SDK 쓰기 0회 |
| 주행 중 승인 | Drive/30 km/h 및 실제 UX 제한 상태에서 알림 버튼 선택, 순정 내비 화면 유지 |
| 승인 결과 | SDK 쓰기 1회. 두 번의 readback 완료 후 리더의 새 검색 목적지와 좌표·ID·sub-ID·provider 일치 |
| 배경 데이터 | 양쪽이 순정 내비를 보면서도 실제 FusedLocation 위치·NaviHelper ETA 전달 |
| 배포본 | v0.4.3 / versionCode 5, release·debuggable=false, 기존 배포 키의 APK v3 서명 |

`tools/verify_background.py`는 실제 시스템 알림 창을 읽고 버튼을 눌러 검사한다. 이후 동일한 release APK로 승인·거절 두 예시를 실제 조작해 녹화했다. SDK 데이터나 시스템 주행 제한을 우회하지 않았다. 알림은 전체 제안과 개인 경로에 묶인 immutable PendingIntent와 비공개 수신기를 사용한다. [동작 및 한계](NATIVE_NAVIGATION.md)

제출 영상은 방 생성·초대부터 시작하는 여행 이야기로 다시 촬영·편집했다. 새 검색 결과인 **두물머리주차장**을 승인한 참여 차량의 순정 내비에 반영했고, 양쪽 여행방에서 `2대 중 2대 도착 시간 확인`을 확인했다. 이어 **세미원**으로의 변경을 거절했을 때 참여 차량의 두물머리주차장 안내가 유지됐다. 이번 영상은 Park 상태이며, 위 Drive/30 km/h 검사를 촬영했다고 표시하지 않는다. [공개 재생 페이지](https://daeho-ai.github.io/moa-trip/) · [영상 흐름과 범위](DEMO.md)

아래는 v0.4.2부터 확인한 기반 동작과 제약의 기록이다. 개인 경유지 호환성·지도 마커 등 미완료 범위는 이번 알림 변경으로 확대하지 않는다.

자동 수용 시험은 debug 빌드에서 SDK 관측 파일을 읽는다. 방 생성·입장·후속 목적지 준비에는 진단 명령도 사용하지만, **일반 승인·거절은 모두 실제 UI 버튼**이다. 오래된 확인키 재전송만 진단 명령으로 주입한다. 별도 배포 영상은 release APK에서 방 생성·참여·공유 설정까지 실제 화면 조작으로 녹화한다. release는 진단 명령을 처리하지 않는다.

GPS·기어·속도는 가상 기기의 시험 입력이다. 위치는 FusedLocation, ETA는 각 순정 내비의 실제 SDK 콜백에서 받으며 앱 내부 예시 데이터로 대체하지 않았다. 에뮬레이터의 ETA는 60초·50m 등 시험값을 반환한다. 실제 도로 교통 예측 정확도나 실차 주행 검증을 뜻하지 않는다.

## 발견하고 수정한 문제

- Linux 기본 네트워크에서는 차량 HAL 초기화가 완료되지 않았다. 이미지가 요구하는 DHCP 주소와 일반 Ethernet 연결 요청을 개발용 실행기에 반영했다. SDK 데이터·시스템 이미지·보안 정책은 변경하지 않았다. [설정 근거와 실행](LINUX.md)
- Intel/NVIDIA 혼합 환경에서 기본 Intel EGL 렌더링이 녹화 중 종료됐다. `--nvidia` 옵션으로 NVIDIA GPU를 선택해 두 대의 구동·녹화를 확인했다.
- 차량용 activity에만 있던 distractionOptimized 선언으로는 Pleos 호스트가 주행 중 앱을 가렸다. application에도 선언하고 실제 주행 제한 상태에서 화면·버튼을 재검사했다. 주행 제한을 끄지 않았다.
- UI의 1초 시계보다 새 SDK 위치가 늦게 도착하면 표본이 미래 데이터처럼 판정돼 직선 거리가 잠시 사라졌다. 판정 시점의 monotonic clock을 사용한다.
- 목적지 확인이 끝나지 않은 상태에서 모호한 대기 문구만 보였다. 실제 위치가 다르면 **‘순정 내비 확인 필요’**와 확인 안내를 표시하고, 무효한 재확인 버튼을 숨긴다.

## 목적지 데이터의 확인된 제약

기본 최근 목록의 42dot은 `37.48544722, 127.03636666`을 반환했지만, 같은 ID를 SDK로 등록하면 현재 검색 결과인 `37.41289678, 127.09383464`로 안내했다. 약 9.5km 차이다. sub-ID를 빈 문자열로 바꿔도 같았다. **목적지 이름만 보고 성공 처리하지 않았다.** 이 경우 기존 위치 불일치 방어가 동작해 WRITE_UNCERTAIN, ETA 제외, 추가 요청 보류가 유지됐다.

순정 내비에서 42dot을 **새로 검색해 선택**하면 출발 앱과 수신 앱의 좌표·식별자가 정확히 일치했다. 수용 시험과 최초 v0.4.3 배포 영상은 이 경로를 사용했다. 이후 제출 영상은 새 검색한 두물머리주차장·세미원을 사용한다. 다른 모든 장소·공급원의 호환성을 검증한 것은 아니다. 최근 데이터가 불일치하면 순정 내비에서 장소를 다시 검색·확인해야 한다. 앱이 잘못 등록된 위치를 자동으로 되돌렸다고 주장하지 않는다.

Connect 2.1.0의 정확한 fingerprint / 위 내비 버전 / 빈 provider에만 조회 시 null sub-ID를 요청 시 `0`으로 전달한다. 원본 조회 값은 보존한다. 다른 플랫폼·개인 경유지에는 이 호환 규칙을 확장하지 않는다.

## 제출 기준과 남은 범위

[공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)에 맞춰 소스, `apk/모아_모아트립_release.apk`, 실행법·에뮬레이터 버전·화면 규격을 포함한 README, 실제 화면 녹화, 작성한 공식 양식을 준비한다. 메일 제출에는 최종 커밋을 기재한다. 신청서 연락처·개별 동의·서명과 실제 이메일 발송은 별도다.

지도 마커, 공동 휴게소, 픽업 최적화, 스티커·음성, 일반 휴대폰 참여는 후속 범위다. 개인 경유지 1/2개의 공급원 호환성과 방문 진행, 외부 HTTPS 운영 서버, 실차 및 Pleos App Market 전체 심사 적합성은 완료로 표시하지 않는다. 호환성을 모르는 개인 경유지는 지우지 않고 목적지 요청을 보류한다.

이 기록은 v0.4.1의 ‘실제 전체 흐름 미검증’ 상태를 갱신한다. 이전 영상의 정적 프로토타입 장면을 이번 SDK 증거로 재사용하지 않는다. 원시 로그·초대 정보·서버 DB·신청서 개인정보는 공개 저장소에 올리지 않는다.

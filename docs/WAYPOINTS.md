# 경유지 함께 들르기

방장이 순정 내비 검색 결과에서 **경유지로**를 선택하면 모아트립이 변경을 확인합니다. 방장이 **일행에게 요청**을 눌러야 참여 차량에 제안합니다. 참여 차량은 순정 내비 위 알림에서 **경유지 추가 / 들르지 않기**를 선택합니다.

승인한 차량에서는 NaviHelper `addWaypoint`를 한 번 호출합니다. 최종 목적지는 유지하며, 개인 경유지가 있으면 그 뒤에 추가합니다. 순정 내비는 최대 2곳을 지원하므로 이미 2곳이면 추가 버튼을 제공하지 않고 기존 경유지 정리를 안내합니다. 같은 곳이 이미 있으면 중복으로 추가하지 않습니다.

경유지 요청은 목적지 계획과 별도로 10분 동안 유효한 방문 요청 ID를 가집니다. 한 번 선택한 요청은 재접속·앱 재시작·경유지 삭제로 다시 적용하지 않습니다. 목적지가 바뀌면 이전 경유지 제안은 만료됩니다. 다시 함께 들르려면 방장이 현재 경유지를 명시적으로 다시 공유합니다. 자동 방문 완료 판단이나 휴게소 추천 기능은 포함하지 않습니다.

## SDK 연결과 판정

| 단계 | 실제 연결 |
|---|---|
| 방장 경유지 감지 | `getWaypointInfo` / `onWayPointInfo`, 기존 경로와 비교 |
| 제안 전달 | 자체 서버의 `stop-proposal`, 차량별 `stop-decision` |
| 승인 후 등록 | `addWaypoint(RequestWaypointInfo)`, 기존 수에 따라 `FIRST` 또는 `SECOND` |
| 완료 확인 | 현재 목적지·경유지 전체 순서·안내 상태를 두 번 독립적으로 재조회 |
| 재시작 보호 | 진행 중 요청과 서버의 방문별 선택을 저장, 반복 SDK 쓰기 금지 |

요청 후 30초 안에 확인되지 않으면 추가 쓰기를 막고 순정 내비 확인을 안내합니다. 시간이 지났다는 이유로 재전송하지 않습니다. ETA는 해당 차량의 실제 최종 목적지 ETA이며 경유지를 포함한 남은 시간입니다. 경유지 선택·반영 확인 중인 차량은 집결 시간 합산에서 제외합니다.

## Connect 2.1.0 호환 처리

검사한 공식 이미지의 Navi Service 3.0.4 / Navigation 3.3.2-rc5-hotfix.3은 경유지 조회에서 좌표를 `0,0`, sub-ID를 null로 반환합니다. 이름·주소·POI ID·순서는 제공됩니다. 이 조합에서는 해당 POI ID와 요청 sub-ID `0`으로 실제 경유지가 등록되는 것을 확인했습니다.

앱은 원본 좌표를 보정하거나 추정하지 않습니다. 정확한 에뮬레이터 fingerprint와 위 패키지 버전, 빈 provider에만 `CONNECT_2_1_POI`라는 경유지 전용 바인딩을 붙입니다. 이 경우 완료 판정은 목적지 좌표와 **경유지의 ID·이름·주소·순서**를 확인하며 경유지 좌표 일치를 검증했다고 표시하지 않습니다. 다른 플랫폼에는 이 예외를 적용하지 않습니다. 목적지 등록에는 계속 유효한 좌표가 필요합니다.

기존 경유지를 묶어서 최종 목적지까지 다시 쓰는 `requestRouteWithWaypoints`의 ID 전용 호환성은 별도 범위입니다. 좌표가 없는 개인 경유지가 남은 상태에서 목적지를 바꾸려 하면 기존 경유지를 지우지 않고 보류합니다.

## 순정 지도 위 다른 차량 표시

위치 공유와 지도에 그리는 권한은 별개입니다. FusedLocation으로 동의한 차량의 위치를 받아 서버로 공유할 수 있지만, 공개 NaviHelper에는 순정 지도에 임의 차량 마커를 추가하는 API가 없습니다. 현재 위치·직선 거리·갱신 시각은 여행방 목록에 표시합니다. 자체 지도 화면은 추가 개발할 수 있으며, 순정 지도 표시는 현대의 별도 인터페이스 지원이 필요합니다.

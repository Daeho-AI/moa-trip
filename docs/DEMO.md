# 방 만들기부터 보는 모아트립 시연

[**▶ 영상 바로 보기 — 로그인 없이 브라우저에서 재생**](https://daeho-ai.github.io/moa-trip/) · [MP4 파일](https://daeho-ai.github.io/moa-trip/video/moatrip-demo.mp4)

**1분 56초 · 2560×1200 · 30fps.** 독립된 Pleos Connect 2.1.0 에뮬레이터 두 대에 v0.4.3 release APK를 설치하고 실제 화면을 조작했다. 왼쪽은 **리더 차량**, 오른쪽은 **참여 차량**이다. 두 화면을 크게 유지하고 상단 역할 표기와 하단 상황 설명을 넣었다.

## 여행 상황과 영상 흐름

차 두 대로 양평 나들이를 떠난다. 주소를 보내고 각자 다시 검색하는 수고, 일행의 도착 시간을 묻는 연락을 줄이는 흐름이다.

1. 리더가 ‘양평 나들이’ 방을 만들고 초대 코드를 전달한다.
2. 참여 차량이 같은 방에 들어온다. 각자 위치·도착 시간 공유를 선택한다.
3. 리더가 순정 내비에서 **두물머리주차장**을 검색하고, 내비 위 알림에서 ‘일행에게 요청’을 누른다.
4. 참여 차량은 재검색하거나 모아트립 앱으로 전환하지 않고 알림에서 승인한다. 순정 내비 목적지가 양수역에서 두물머리주차장으로 바뀐다.
5. 여행방에서 두 차량 사이의 직선 거리와 각 순정 내비의 도착 시간을 확인한다.
6. 리더가 만날 장소를 **세미원**으로 바꿔 다시 요청한다. 참여 차량이 ‘현재 목적지 유지’를 선택하면 두물머리주차장 안내가 그대로 유지된다.

## 녹화 범위

방 생성·참여, 승인, 거절을 각각 실제로 조작한 세 녹화 구간을 이어 편집했다. 이름·초대 코드는 실제 화면의 입력란에 넣었고 목적지는 순정 내비의 새 검색 결과에서 골랐다. 대기 시간을 일부 잘랐으며 앱 화면이나 SDK 값을 합성하지 않았다. 위치·ETA 목록은 여행방에서, 목적지 변경 확인은 순정 내비 위 시스템 알림에서 보여준다.

이번 여행 시연은 두 에뮬레이터의 **Park 상태**에서 촬영했다. 위치는 가상 기기에 입력한 좌표를 FusedLocation으로 수신하고 ETA는 NaviHelper에서 받는다. 실차 주행이나 도로 교통 예측 정확도의 검증은 아니다. Drive/30 km/h 상태의 승인·거절 및 배경 공유 검사는 [별도 검증 기록](VERIFICATION.md)에 있다.

공개 영상에 보이는 촬영용 초대 코드는 만료 처리했다. 원본 녹화와 검사 자료는 개발 작업 폴더에 보관한다. 최종 파일 해시·길이·확인 항목은 [영상 검증 정보](verification/release-ui.json)에 기록한다.

현재 다른 차량의 위치는 **여행방 목록**으로 제공한다. 순정 지도 위에 임의 차량 마커를 그리는 API는 공개 NaviHelper에서 확인되지 않았다. [순정 내비 연동 범위](NATIVE_NAVIGATION.md)

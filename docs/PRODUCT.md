# 모아트립 제품 설계

**v0.4 우선 규칙:** 리더의 공유 확인과 각 차량의 목적지 변경 확인이 매번 필요하다. 이전 자동 따라가기 동의로 내비를 쓰지 않는다. 현재 화면·동작은 [REVIEW_02](REVIEW_02.md)와 [IMPLEMENTATION](IMPLEMENTATION.md)을 따른다. 나머지 확장 설계는 구현 완료를 뜻하지 않는다.

2026-11-13 · v0.2 · 사용자 관점 1차 보정 · 가칭 MoaTrip

## 1. 제품 정의

친구·가족이 차 2~5대로 여행할 때 목적지를 각자 다시 입력하거나, 위치·도착 시간을 계속 전화로 확인하는 수고를 줄인다. 순정 내비를 이용하는 실제 차량 앱과 여행방을 연결하고, 함께 쉬고 만나는 과정까지 돕는다.

한 줄 소개: **차 여러 대로 떠나는 여행에서 목적지·휴게소·일행의 위치와 도착 시간을 함께 맞추고, 필요한 사람까지 편하게 태워 가는 여행 앱.**

2번 아이디어가 본체다. 3번은 `여행방 → 픽업 → 이 차량이 태울 사람`으로 통합한다. 이전 별도 픽업 앱을 만들지 않는다. 장르·핵심 흐름·SDK 선택은 이 설계를 기준으로 하고 이름과 화면 문구는 이후 보정한다.

## 2. 첫 버전의 기능

| 기능 | 사용자 경험 | 첫 버전 범위 |
|---|---|---|
| 여행방 | 초대 코드로 일행만 입장 | 2~5대, 차량별 닉네임·아이콘, 12/24/72시간 선택, 진행 중 방 복귀 |
| 리더 목적지 공유 | 리더가 순정 내비에 찍고 공유를 확인하면 각 차에 제안 | 차량마다 이번 변경을 확인한 뒤 반영, 실제 반영 결과 표시 |
| 위치·ETA | 어디쯤 오는지, 언제 만날지 확인 | 자체 지도와 차량 카드, 최종 목적지·다음 공동 경유지 ETA |
| 휴게소·공동 경유지 | 같은 휴게소에서 만나기 | 출발 전 합의한 경유지 반영, 주행 중 새 휴게소는 차량별 들르기/직행 선택 |
| 이모티콘·짧은 표현 | 확인·휴식·대기를 짧게 전달 | 고정 프리셋, 수신자 선택 또는 전체 전송, 반복 전송 제한 |
| 집결 예상 | 일행이 모이는 시각 파악 | 같은 장소의 예상 시각과 확인된 차량 수. 누락 차량이 있으면 전체 집결 시각으로 표시하지 않음 |
| 출발 준비 | 휴게소에서 먼저 출발하는 상황 줄이기 | 준비·휴식·주유·대기, 이번 경유지에 참여한 차량만 집계 |
| 픽업 통합 | 승객이 조금 걸으면 유리한 장소 비교 | 차량당 활성 픽업 1건, 승객 1명, 검토 후보 최대 6곳, 상위 3개 |

핵심 위치·ETA는 참가 차량의 앱이 직접 읽고 공유한다. 다른 현대차 소유자의 위치를 일괄 조회하지 않는다. 스마트폰만 참여한 사람은 `동승자/픽업 승객`으로 구분하며, 순정 내비 ETA를 가진 차량으로 표시하지 않는다.

## 3. 대표 여행 흐름

1. A가 방을 만든다. 이미 순정 내비에 목적지가 있으면 현재 목적지 카드를 확인해 여행 목적지로 사용한다. B와 C는 초대 코드로 들어와 현재 계획과 공유 범위를 확인한다. 늦게 합류해도 다음 변경을 기다리지 않는다.
2. A가 순정 내비에 캠핑장을 설정하고 ‘일행에게 요청’을 누른다. B와 C는 장소를 보고 각각 ‘목적지 변경’ 또는 ‘현재 목적지 유지’를 선택한다. 화면에는 `B 같은 목적지 / C 변경 확인 대기`처럼 실제 상태가 보인다.
3. C는 친구를 태워야 한다. 승객 링크에서 현재 위치와 도보 3분 허용을 받는다. 원래 장소와 대안을 비교하고 승객 동의·C의 확정·내비 반영 확인을 마친다. 그 뒤 승객에게 출발 안내를 보여준다. 확정 장소는 이동 중 새 추천으로 바꾸지 않는다.
4. B가 화장실 프리셋을 보낸다. A가 휴게소를 공동 장소로 제안한다. A와 B는 들르기를 선택하고 C는 직행한다. 아직 답하지 않은 차량은 참여 미정으로 남긴다. 이미 지나쳤거나 다른 방향에 있는 차량을 자동으로 되돌리지 않도록 주행 중 새 휴게소는 동의 전 내비에 쓰지 않는다.
5. 지도에는 차량 아이콘, 카드에는 휴게소·최종 목적지 ETA가 표시된다. 숫자가 오래됐거나 목적지가 다르면 비교에서 빠진다.
6. 휴게소에 도착한 A와 B가 준비 상태를 확인한다. 참여한 차량 전체의 준비가 확인되면 리더에게 한 번 알린다. 미도착·응답 없음은 준비 완료로 간주하지 않는다.
7. 먼저 도착한 사람은 ‘나는 여행 종료’를 선택한다. 자신의 공유만 끝난다. 본인의 픽업이 진행 중이면 탑승 완료 또는 픽업 취소를 먼저 처리한다. 리더는 다른 차량과 픽업이 아직 진행 중인지 확인한 뒤 전체 방을 종료할 수 있다. 누구의 순정 안내도 임의로 취소하지 않는다.

## 4. 목적지 자동 등록의 정확한 의미

참여 자체는 내비 변경을 허용하지 않는다. 현재 여행 목적지와 기존 개인 경로를 바탕으로 변경 확인을 표시한다. 위치와 ETA 공유는 별도의 명시적 선택이며 참여 설정에서 각각 끌 수 있다. 공유하지 않아도 방 참여는 가능하다.

리더 목적지는 변경마다 리더가 공유를 승인하고, 각 차량도 그 목적지로 변경할지 승인한다. 무응답·닫기·거절은 현재 목적지를 유지한다. 공동 경유지 확장에서도 승인한 계획 밖의 장소를 조용히 추가하지 않는다. 주행 중 새 휴게소는 각 차량이 들르기/직행을 선택한다. 원래 내 목적지를 다른 값으로 바꿔 놓고 ‘경유지만 반영’이라고 표시하지 않는다.

리더 화면에는 ‘내 목적지를 일행에게 공유 중’ 상태와 일시중지를 표시한다. 개인 용무로 다른 최종 목적지를 입력할 때는 공유를 잠시 멈출 수 있다. 재개할 때 현재 목적지를 확인한다. 검색 미리보기·단순 재탐색·남은 시간 변화·안내 종료는 공동 목적지 변경으로 취급하지 않는다. **공유 범위는 최종 목적지와 명시한 공동 경유지다.** 리더의 개인 픽업은 공유하지 않는다.

새 최종 목적지로 바꾸는데 방문 전 공동 경유지가 남아 있으면, 리더에게 그 경유지를 유지할지 정리할지 한 번 확인한 뒤 묶어서 게시한다. 잘못된 방향의 이전 휴게소까지 자동 승계하지 않는다. 다른 차량마다 목적지 변경을 재승인받는다.

각 차량은 자신의 경로 옵션과 개인 경유지를 유지한다. 목적지·경유지를 직접 바꾸면 ‘내 경로 우선’으로 전환한다. 통행료 회피 같은 경로 옵션만 바꾸거나 정상적으로 경유지를 통과한 것은 탈동기화로 처리하지 않는다. 불명확한 변경은 경로를 덮어쓰지 않고 확인 상태로 둔다.

방문 완료·건너뛰기는 차량별로 기록한다. 재접속해도 이미 지난 휴게소나 탑승을 마친 픽업을 다시 넣지 않는다. 개인 경유지와 새 공동 경유지의 선후 관계가 불명확하면 순서를 한 번 선택하며 자동으로 임의 순서를 만들지 않는다.

권한 거부, 지원되지 않는 장소, 연결 단절, 정책상 대기 상태에서는 자동 등록 완료라고 표시하지 않는다. 리더에게는 차량별 결과가 보이고, 실패한 한 차량 때문에 이미 성공한 차량을 되돌리지 않는다.

## 5. 화면 구성

기본 사용 형태는 **순정 내비 옆에 모아트립 여행 패널**이다. Pleos의 앱 윈도우 배치는 사용자가 조절한다. 앱이 Driving view를 가리거나 순정 지도에 임의 마커를 덧그리지 않는다.

| 화면 | 주요 구성 | 기본 동작 |
|---|---|---|
| T01 시작 | 진행 중 여행 복귀, 만들기, 코드로 참여 | 주차 상태에서 생성·참여, 차량당 활성 방 1개 |
| T02 참여 설정 | 현재 목적지, 함께 길 안내/내 경로, 공유 선택 | 기존 내 경유지와 변경되는 최종 목적지 미리보기 |
| T03 여행 패널 | 다음 공동 장소, 차량별 ETA·반영 상태, 짧은 상태 | 좁은 윈도우에서는 카드 우선 |
| T04 여행 지도 | 자체 지도, 차량 위치, 목적지·공동 장소 | 넓은 윈도우에서 지도와 목록 병행 |
| T05 일정/경유지 | 최종 목적지, 공동 경유지, 나만의 픽업 | 공동/개인 범위 구분, 순서 미리보기 |
| T06 휴게소 | 들르기/직행/미정, 도착·준비 상태 | 미정·연결 끊김 수를 함께 표시, 직행 차량 제외 |
| T07 픽업 비교/만남 | 비교 카드 또는 확정 장소·만남 상태 | 확정 후에는 고정 장소 안내, 재추천 목록을 앞세우지 않음 |
| T08 표현 보내기 | 커피, 화장실, 확인, 기다릴게, 거북이 등 | 주차 상태에서 이용, 동승자 웹에서도 이용 |
| T09 동기화 확인 | 전달·적용 중·완료·충돌·연결 대기 | 본인 경로 유지/다시 동기화 |
| W01 동승자 웹 | 방의 허용된 상태, 준비·프리셋 | 차량 앱에서 일회성 연결 승인, 경로 변경 권한 없음 |
| W02 픽업 승객 웹 | 현재 위치/수동 핀, 걷기 한도, 만남 후보 | 픽업 건에만 접근, 방 전체 위치 열람 불가 |

좁은 화면 예시:

```text
양평 캠핑 여행                 3대 참여
다음 만남  ○○휴게소            변경 반영 2/3
리더 A     약 14:08             반영 완료
B          약 14:11             반영 완료
C          픽업 중              이번 휴게소 직행
휴게소 참여 2대 모두 확인       주행 기준 약 14:11
[쉬고 싶어요] [내 상태]         허용되는 상태에서만
```

표시된 시각은 구성 예시다. A/B 중 한 대의 ETA가 없으면 ‘1/2대 확인 · 전체 집결 시각 확인 중’으로 바뀐다. 목적지가 다른 차는 ‘다른 목적지’, 미응답 차량은 ‘참여 미정’으로 따로 표시한다. 순정 ETA는 휴식·탑승 시간을 모두 포함하는 여행 일정 예측이 아니다.

차량 목록은 참여 순서로 고정하고 선택한 차량만 강조한다. ETA가 바뀔 때마다 순위를 뒤집지 않는다. 연결이 끊겨 지도 마커를 숨겨도 차량 카드는 ‘마지막 갱신’과 함께 남긴다. 주행 화면은 다음 만남·일행 상태·필요한 알림만 보여주고, 지도 상세·일정 편집·스티커 목록은 별도 화면으로 둔다.

## 6. 이모티콘을 살리는 방향

‘거북이’, ‘빨리 와’ 같은 친근한 장난 표현은 유지하되 주차/동승자 화면의 스티커로 둔다. 운전자 주행 화면은 `기다릴게`, `천천히 와`, `휴게소 들르자`, `확인` 같은 짧은 상태를 우선한다. 속도 순위·도착 경쟁·속도에 따른 보상은 넣지 않는다.

수신 이모티콘은 자체 앱 카드에 작게 표시한다. 순정 지도 위로 날아가는 효과는 없다. 복잡한 텍스트·프리셋 목록·애니메이션은 CarUxRestrictions와 앱 카테고리의 허용 범위에 따라 제한한다. 정지 속도 0만으로 주차했다고 판단하지 않는다.

음성 안내는 내 차의 목적지 변경 결과, 합의한 휴게소 변경, 모두 출발 준비 등 필요한 사건만 알린다. 다른 차량 4대의 적용 성공을 각각 읽지 않고, 같은 사건은 한 번으로 합친다. 이모티콘은 기본 무음이며 중요한 안내만/모두 무음 설정을 제공한다. 내비의 오디오 포커스를 따른다. 음성 인식은 다음 단계이며 STT가 없는 첫 버전의 필수 흐름을 음성 명령에 의존시키지 않는다.

휴식 요청은 차량별로 합산한다. 같은 차의 운전자와 동승자가 모두 커피를 눌러도 2대로 세지 않는다. 요청은 10분 또는 해당 휴게소 방문 시 만료하고 직접 철회할 수 있다. 단순 메시지 수신을 휴게소 참여 동의나 내비 반영으로 해석하지 않는다.

| 3 | 음성으로 휴식 요청·확인 전송 | STT 실환경 검증, 의도 매핑, 확인 절차 |
| 4 | 여러 날 여행 일정·여러 공동 정차 | 앱 일정과 순정 활성 경유지의 구간별 연결 |
| 5 | 다수 픽업·차량 배정 최적화 | 여러 승객 동의, 좌석 입력, 경로 호출량 증가 |
| 6 | 충전/식당 예약·비용 정산 | 별도 제휴·결제·실시간 시설 데이터 |

첫 버전은 공동 경유지와 개인 픽업을 합쳐 **동시에 순정 내비에 요청하는 경유지를 최대 2개**로 제한한다. 공개 요청 인덱스 FIRST/SECOND를 기반으로 한 제품 범위이며, 플랫폼 전체 최대치라고 단정하지 않는다. 자리가 부족하면 기존 개인 경유지를 자동 삭제하지 않고 정차 후 조정을 요청한다.

## 8. 완료와 보류의 기준

첫 실행 가능한 단계는 방 참여→리더 목적지 전달→두 차량 위치/ETA 확인이다. 이후 휴게소 조율, 마지막으로 픽업을 연결한다. 동승자 웹·스티커·음성이 이 핵심 검증을 늦추지 않게 한다.

방 만료는 15분 전에 알린다. 연장하더라도 개인 공유 동의의 만료시간을 자동 연장하지 않는다. 리더 연결이 끊겨도 현재 계획·각 차의 순정 안내는 유지한다. 첫 버전은 자동 리더 선출 대신 명시적 양도를 사용한다. 단독 리더가 오랫동안 복귀하지 못하는 상황의 대체 리더 기능은 후속 확장으로 남긴다.

현재 확정하는 것은 제품 방향과 구현 계약이다. 두 차량의 실제 내비 쓰기, FusedLocation 갱신, TTS·STT, 외부 길찾기 계정, 지도 공급은 아직 이 앱으로 실행 검증하지 않았다. 이 항목은 개발 초기에 확인한다.

GitHub 공개와 시연 영상은 앱이 동작하고 설계 보정을 거친 다음 진행한다. 장소 추천의 전국 최적성, 순정 지도 오버레이, 전 차량 원격 제어는 현재 범위에 넣지 않는다.
